  4. В цикле создаются 10 потоков. Каждый поток выполняет функцию, которая увеличивает значение counter на 1 в течение 1,000,000 итераций.
     a) Поскольку несколько потоков одновременно увеличивают общий счетчик counter, это может привести к конфликтам между потоками. В результате значение counter может быть меньше ожидаемого (10,000,000), поскольку потоки могут перезаписывать значение друг друга. То есть счетчик должен увеличиться на 10000000, но итого в **результате** мы видим числа около 2000000(+-), время выполнения около 1 секунды.
     b) Версия с мьютексом. Здесь создаётся объект мьютекса mtx. Он будет использоваться для управления доступом к переменной counter. Когда создаётся объект lock, он вызывает метод lock() у объекта mtx, который блокирует мьютекс. Если другой поток уже захватил этот мьютекс, текущий поток будет ждать, пока мьютекс не будет освобождён. После выполнения инкремента counter++, объект lock выходит из области видимости (например, когда завершится лямбда-функция), и деструктор lock_guard автоматически вызывает метод unlock(), освобождая мьютекс. **Результат**: counter = 10000000, время выполнения: Около 30 секунд!!!
     c) Версия где тип переменной counter std::atomic<int> - все операции над данной переменной выполняются атомарно, то есть операции выполняются без конфликтов между потоками. **Результат**: counter = 10000000, время выполнения: Около 2 секунд

Итог:
Способы решения проблем синхронизации

1. Мьютексы: Это объекты, которые используются для защиты критических секций — участков кода, которые могут выполняться только одним потоком в данный момент времени. Поток должен захватить мьютекс перед выполнением критической секции и освободить его после завершения.

2. Атомарные операции: Эти операции гарантируют, что чтение и запись переменной происходят как единое целое, без возможности прерывания другими потоками. Это позволяет избежать состояния гонки без использования мьютексов.
